# FLODSS AI Decision Explanation (Phase 12 Architecture & Engineering Audit)

## 1. System Role & Strict Operational Boundaries

Google Gemini serves strictly as an **explanation and natural-language interpretation service** within FLODSS (Facility Layout Optimization Decision Support System).

### What Gemini DOES:
- Explains deterministic optimization outcomes produced by FLODSS algorithms.
- Interprets geometric constraint satisfactions, violations, and penalty costs.
- Explains why the Adaptive Strategy Engine selected a specific algorithm archetype.
- Explains multi-objective trade-offs between Pareto-optimal candidate layouts.
- Formulates user-friendly executive summaries and answers grounded engineering questions.

### What Gemini DOES NOT (and CANNOT) DO:
- **Never an optimization engine**: Gemini does not place departments, compute coordinates, or run heuristic swaps.
- **Cannot alter metrics**: Canonical evaluation metrics (Material Handling Cost, Relationship Satisfaction %, Soft Constraint Penalties) are computed solely by `CanonicalEvaluationService` and cannot be overwritten by LLM responses.
- **Cannot execute system actions**: The explanation service is read-only and stateless.

---

## 2. Confidentiality-First Design & Privacy Policies

FLODSS is an advanced industrial engineering and research platform. To prevent data leakage and protect proprietary manufacturing designs:

1. **Disabled by Default**:
   - `AI_ENABLED=false` is enforced across all configurations (`backend/app/core/config.py`).
   - The user interface defaults to **Explain Locally (Offline & Deterministic)**.
2. **Explicit User Consent**:
   - No data packet is transmitted to Google Gemini without the user clicking **Preview Data Packet**, inspecting the sanitized fields, reviewing excluded sensitive data, and explicitly checking the consent checkbox.
3. **Cryptographic Consent Binding**:
   - Consent is bound to the exact SHA-256 payload fingerprint via an HMAC-SHA256 signed `UserConsentToken`.
   - Modifying a single character or parameter invalidates the consent token, preventing parameter injection or altered context transmission.
   - Tokens expire automatically after 15 minutes.
4. **Zero Proprietary Data Transmission**:
   - **Zero Source Code**: No algorithm implementations, scripts, or git metadata are ever transmitted.
   - **Zero Spatial Coordinates**: Origin $(x, y)$, widths, and heights are strictly stripped.
   - **Zero Raw Flow Matrices**: Pairwise flow volumes ($F_{ij}$) and unit material handling cost rates ($C_{ij}$) are excluded.
   - **Zero Proprietary Department Names**: Department names are anonymized to generic tokens (`Dept 1`, `Dept 2`, etc.).
   - **Zero Environment Variables / Keys**: API keys and secrets reside exclusively on the backend server.

## 3. Local vs Cloud Explanation Paths

FLODSS provides two independent explanation engines:

| Feature / Dimension | Local Deterministic Explainer | Gemini Cloud Explainer |
|---|---|---|
| **Execution Mode** | 100% Offline (Local CPU) | Google Gemini API (`gemini-3.8-flash`) |
| **Network Access** | Zero network calls | HTTPS to Google GenAI API endpoint |
| **API Key Required** | None | Yes (`GEMINI_API_KEY`) |
| **Cost** | Free ($0.00) | Standard Gemini API token rates |
| **Deterministic** | 100% reproducible | Heuristic generative output (temp = 0.2) |
| **Default Mode** | **YES (Default)** | Opt-in with explicit cryptographic consent |
| **Fallback Target** | Primary baseline | Automatically falls back to Local Explainer |

## 5. Security Guardrails & Output Validation

Every explanation generated by Gemini passes through `ExplanationOutputValidator` before reaching the user:

1. **Forbidden Algorithm Hallucination Filter**:
   - Rejects mentions of algorithms not implemented in FLODSS v1 (e.g. Simulated Annealing, NSGA-II, MILP, Particle Swarm).
2. **False Mathematical Optimality Filter**:
   - Because the Facility Layout Problem is strongly NP-hard, any statement claiming a solution is "proven globally optimal", "mathematically optimal", or "guaranteed global optimum" is rejected.
3. **Numeric Financial Grounding**:
   - Significant financial figures ($ > \$500) cited in text are cross-referenced against canonical metrics ($\text{MHC}$, $\text{Soft Penalty}$) with a 15% tolerance window. Ungrounded financial fabrications are rejected.
4. **Mandatory Disclaimer**:
   - Enforces the inclusion of the NP-hard heuristic disclaimer acknowledging that no mathematical guarantee of global optimality exists.
5. **Prompt Injection Mitigation**:
   - User inputs are limited to 300 characters, stripped of HTML tags/brackets, and checked for prompt injection phrases ("ignore previous instructions", "reveal system prompt").

## 6. Failure & Fallback Handling

If any of the following occur during a Gemini request:
- Network disconnect or timeout (`GEMINI_TIMEOUT_SECONDS = 15.0`)
- Invalid API key or quota exhaustion
- Malformed JSON returned by the LLM
- Failure during `ExplanationOutputValidator` verification

The service catches the failure, logs a detailed error, and **automatically falls back to `LocalDeterministicExplainer`**.
The response is tagged with:
```json
{
  "mode": "local",
  "fallback_to_local_used": true,
  "fallback_reason": "Gemini API call failed (TimeoutError): Gemini API connection timed out after 15s"
}
```
This guarantees 100% operational uptime and prevents application dead-ends.

## 8. Known Limitations

1. **Heuristic Explanations**: Gemini generates semantic explanations of heuristic algorithms; it does not solve NP-hard mathematical proofs.
2. **Language Coverage**: Standard prompt engineering and deterministic templates are currently optimized for English industrial terminology.
3. **No 3D Clearances**: The current FLODSS model is 2D planar rectangular layout; vertical multi-story piping, overhead cranes, and vertical clear heights are not yet represented.
